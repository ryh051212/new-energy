# 规划基础数据接入说明

接入日期：2026-10-27。原始交付保存在 `weidu_data/`，项目运行时读取 PostgreSQL/PostGIS 与 `data/processed/` 当前快照。后端保持项目现有 FastAPI 架构，空间接口提供 WGS84 GeoJSON，显示时由前端按底图需要转换。

| 充电地点 | 247 个真实地图地点：区内 201、周边 46；清除原有演示补全属性；未知快慢充使用灰色待核实图标 | 地图与 `/api/stations`；区内筛选 `?scope=weidu` |
| 功能 POI | 1,993 条；住宅 224、工作 379、商业 406、休闲 222、公共服务 762；保留原类别与统一类别 | POI 图层、`/api/facility-pois`；住宅与商业旧接口同步更新 |
| 道路 | 2,987 条道路、16,804 节点、28,705 有向边，约 10 km 周边范围 | OSM 图层、`/api/osm-roads`、`/api/osm-roads/network` |

当前空间参考快照仍为 460 条，包含 172 用地、199 停车、34 入口、39 水域、10 电力、6 风险参考。采集包的停车记录可能在旧参考中按“入口”表示，不能直接相加。建筑轮廓未取得，没有生成虚构建筑。

原 240 条虚拟站以 `status=retired` 归档，数据库保留以便回溯；地图和道路研究不把它们作为现有供给。站点总表物理行数 487 并不表示有 487 个真实地点。快慢充、枪数、公共开放、价格与实时空闲保持未知；两处有历史证据的设备信息按已有逐字段证据展示，不能解读为实时状态。

## 使用方式与研究限制

```text
① 打开空间供需 → 分析面板
   ├─ 站点与供需：读取更新后的站点、功能 POI 和网格统计
   ├─ 基础数据 → 模型人口 → 在地图查看：按需载入人口网格图层
   ├─ 基础数据 → 分时曲线：切换工作日、周末与节假日
   └─ 基础数据 → 数据来源：查看来源、缺失与获取状态
② 道路分析 → 读取新路网与区内、周边真实地点 → 返回速度情景下的分析结果
```

人口栅格总和 892,502.84，与政府简介人口存在明显口径差异，未按 50 万人强制校准。网格已归属 891,919.92 人，另有 197 个像元、582.92 人未归属，明确保留在元数据中。它是模型预测人数，当前只作空间分布参考；既有 POI 活动模型没有悄悄变成人口或真实订单模型。

分时曲线的单位是“时点车辆状态比例”，包括私人和公共地点充电。它只提供外部观测参考，未替换现有活动情景系数，不能当作魏都区公共到达率、每日充电概率或真实负荷。

道路分析使用 239 个未被范围审查标记的地点，其中区外 42 个；8 个重卡、公交、出租或换电等需核对地点不进入默认私人车供给。公共开放条件仍未核实，结果属于“已记录地点提供服务”的情景。速度、信号延误与统一单站容量也是情景参数，不能称为实时驾车时间或真实设施供给能力。完整道路分析响应通过 `quality.boundaryContextStations` 与 `quality.supplyAccessBasis` 标明这一口径。

POI 与充电地点受到地图接口结果窗口限制，不能声称完整名录。边界年代与许可仍需补证；当前边界面积约 90.1093 km²，与政府公开面积存在差异。数据采集、质量检查及许可详情见 `weidu_data/README.md` 和 `weidu_data/metadata/data_sources.csv`。

## 更新与备份

脚本：`backend/scripts/integrate_planning_data.py`。在项目根目录执行：

```powershell
# 默认只验证事务，回滚数据库，不启用新快照
.\backend\.venv\Scripts\python.exe -X utf8 backend/scripts/integrate_planning_data.py

# 先完整备份，再接入经过采集验证的数据
.\backend\.venv\Scripts\python.exe -X utf8 backend/scripts/integrate_planning_data.py --apply
```

需要本项目数据库连接、Rasterio、PyProj，以及 `pg_dump`。脚本默认匹配本项目 PostgreSQL 17、localhost:5433、nev_webgis；不同环境应先调整备份命令，`PG_DUMP_PATH` 可指定可执行文件。真实记录 ID 缺失时脚本拒绝覆盖；更换快照前也应核查公开证据是否有更新。

本次备份：`backend/backups/planning_baseline_20261027_201405/`，含 `before.dump` 和原道路、拓扑、空间参考文件。应用结果见 `docs/reports/planning-baseline-integration.json`。导入先提交数据库再更新运行快照，运行期间应避免并发导入；文件写入失败时按报告和备份核对并重新执行，不将部分完成视为接入成功。
