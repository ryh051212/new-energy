## 代码与执行流程

```text
① MapView 的 setup 创建 useStationSearch 实例
↓ 模板渲染与挂载；onMounted 创建地图；地图 load 后加载正式数据
② 用户输入名称 → schedulePoiSearch 清除旧计时、取消旧请求
├─ 正在用中文输入法组词 → 等 compositionend
├─ 空输入 → 清空建议并停止加载
└─ 300 ms 无新输入 → searchStation({ suggestions: true })
   ↓ await api/poiSearch.js 的 searchPois
③ GET /api/pois?q=… → backend/poi_search.py 的 search_pois
   ↓ 固定来源表 → 参数化 ILIKE → 研究区 ST_Covers → 排序与限制数量
   ↓ ST_X / ST_Y 序列化 WGS84 坐标；finally 关闭数据库连接
④ 前端校验响应并转为 Feature
├─ 已取消、迟到或组件已卸载 → 忽略响应
├─ 无结果 → 显示无内容提示
├─ 服务失败 → 标明本地已载入数据的降级结果
└─ 成功 → 更新建议；输入阶段不自动移动地图
⑤ 用户点击建议或用方向键与 Enter 选择
   ↓ selectSearchStation → MapView 的 onSelect
   ↓ toMapGeoJSON 按当前底图转换显示坐标 → flyTo → Popup 与成功提示
⑥ 用户离开地图 → onBeforeUnmount → disposeSearch
   ↓ 清除防抖、取消请求、移除监听；其他地图工具继续按原流程释放资源
```

`backend/poi_search.py` 对应讲义的模型查询、序列化与视图职责，`backend/main.py` 注册路由。前端事件集中在 `useStationSearch.js`，API 集中在 `api/poiSearch.js`，模板、飞行和弹窗由 `MapView.vue` 连接。

## 修复的问题与保留的准则

- 自动建议补齐了原来只点击按钮搜索的缺口；手动提交时的单结果直达、搜索历史与站点完整信息继续可用。
- 将统一 POI 查询与原站点列表接口分开，搜索不替换地图全部站点，也不修改建站草稿、需求权重或规划计算模型。
- 为每次输入建立请求版本与取消信号，避免旧查询在清空、关闭或新输入后重新打开列表；卸载释放计时与监听。
- 搜索项使用来源与 ID 区分，同名地点可分别选择；仅以名称作唯一键会产生错误定位，因此未照搬该细节。
- 沿用项目 FastAPI、PostGIS、WGS84、同源 Cookie 和真实数据来源准则。没有把地图采集记录解释成现场核验，也没有把直线距离解释成导航距离。
- 目录迁移遗留的一处历史车主端测试样本相对路径已修正；恢复该回归检查，不重新启用已下线车主端。
