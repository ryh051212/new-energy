# 魏都区充电设施 WebGIS —— 项目逻辑梳理

> 本文只描述"当前代码实际在做什么"，所有数字均为在现有数据上实测所得。
> 文末有一份按优先级排列的问题清单，供后续整理时参考。

---

## 一、项目定位

一个单页地图应用：以许昌市魏都区行政边界为范围，展示区内的电动汽车充电站，
并用 **0.5 km 边长的六边形网格** 做供给密度分级，配合右侧面板做统计与分布图。

数据来自高德 POI 接口，**离线预处理成静态 GeoJSON**，前端只做读取和展示，
没有后端、没有数据库、没有实时接口。

---

## 二、技术栈与入口

| 项 | 内容 |
| --- | --- |
| 框架 | Vue 3（`<script setup>` 组合式 API） |
| 构建 | Vite 8 + `@vitejs/plugin-vue` |
| 地图 | MapLibre GL 6（无外部底图瓦片，style 全部内联在 `MapView.vue`） |
| 空间计算 | Turf 7（`booleanPointInPolygon` / `bbox` / `hexGrid` / `union`） |
| 图表 | ECharts 6（柱状图） |
| 抓数 | 高德 Web 服务 API + dotenv 读 `.env.local` 里的 `AMAP_KEY` |

入口链：`index.html` → `src/main.js` → `src/App.vue` → `src/components/MapView.vue`。

`App.vue` 只有 7 行，唯一职责就是挂载 `MapView`，没有任何路由和状态管理库。

## 四、离线数据管线

### 4.1 全景

```
                 node scripts/fetchAmapStations.mjs        （仅需重新抓数时执行）
 高德 place/text ─────────────────────────────► data/raw/amap-stations.json
 keywords=充电站                                             200 条 POI
 region=许昌市 city_limit=true
 page_size=25，最多 20 页，间隔 1.2s，429/5xx 重试 3 次
                          │
                          ▼  node scripts/convertStations.mjs
                    convertPois()     去重 + 坐标校验 + 字段映射
                          │
                          ▼
               data/processed/stations-gcj02.json   193 条
                          │
                          ▼  node scripts/filterWeiduStations.mjs
                    filterStations(stations, weidu.json)
                     空间筛选：点是否落在边界多边形内
                          │
              ┌───────────┴───────────┐
              ▼                       ▼
 data/processed/weidu-stations.json   public/geojson/stations.json
              └─────── 两份内容完全相同，一次生成 ───────┘   52 条
                          │
                          ▼  node scripts/buildHexGrid.mjs
              turf.bbox(魏都区) → turf.hexGrid(bbox, 0.5km, {mask: 魏都区})
                          │  170 格
                          ▼
                    countHexStations(grid, 筛选后站点)
                          │  逐格统计，每个站点最多计入一格
                          ▼
               public/geojson/hex-grid.json   170 格 / 137 格为空 / 合计 52
```

**执行顺序不能颠倒**：`buildHexGrid.mjs` 读的是 `public/geojson/stations.json`，
也就是 `filterWeiduStations.mjs` 的产物。顺序错了就会用旧站点算网格。

### 4.2 各步骤实测损耗

| 环节 | 输入 | 输出 | 丢失原因（已实测） |
| --- | --- | --- | --- |
| 抓取 | 高德接口 | 200 条 | — |
| `convertPois` | 200 | 193 | 7 条**重复 ID**（同 ID 保留最后一条有效记录） |
| `filterStations` | 193 | 52 | 141 条不在魏都区边界内 |
| `countHexStations` | 52 | 合计 52 | 无遗漏（有遗漏会直接抛错，不会静默） |

### 4.3 三个可复用函数（`src/utils/`）

| 函数 | 文件 | 职责 | 被谁使用 |
| --- | --- | --- | --- |
| `validCoordinates(c)` | `stations.js` | 坐标必须是长度 ≥2 的数组、有限数、经纬度范围合法 | `convertPois`、`filterStations`、`hexGrid.js` |
| `convertPois(pois)` | `stations.js` | 高德 POI → GeoJSON Feature；`id:` / `row:` 前缀做去重键 | 脚本 + 测试 |
| `filterStations(stations, boundary)` | `stations.js` | 点落在任一行政区块内即保留（支持 FeatureCollection 与 MultiPolygon，自动排除洞内点） | 脚本 + 测试 |
| `countHexStations(grid, stations)` | `hexGrid.js` | 复制网格 → 逐格计数 → 校验有无站点漏出网格；不改动入参 | 脚本 + 测试（**页面另有一份内联实现，见问题 1**） |

### 4.4 站点字段

`convertPois` 产出的 properties：

```
id, name, type, address, district(=adname), city(=cityname),
coordSystem: 'GCJ-02',
chargeType: 'fast' | 'slow' | 'unknown'
```

实际数据中 **52 条全部是 `unknown`**——高德返回的 POI 里没有可靠的快慢充字段，
所以 `['fast','slow'].includes(...)` 永远不成立。

## 五、运行时逻辑（`MapView.vue`）

### 5.1 初始化（同步，`onMounted`）

创建一个 MapLibre Map，`center: [113.85, 34.04]`、`zoom: 11`，style 完全内联：

**3 个 source**

| source | 初始数据 |
| --- | --- |
| `weidu` | `/geojson/weidu.json` |
| `stations` | `/geojson/stations.json` |
| `hexgrid` | 空 FeatureCollection（等统计完再塞数据） |

**8 个 layer（自下而上）**

| # | id | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | `background` | background | `#f1f5f9` 纯色底，无瓦片底图 |
| 2 | `weidu-fill` | fill | 边界填充 `#38bdf8`，透明度 0.4 |
| 3 | `hexgrid-fill` | fill | 颜色读 feature 的 `color` 属性，透明度 0.65 |
| 4 | `hexgrid-highlight` | fill | 图表选中的网格，`#f63465`；初始 filter 匹配不存在的 -1 |
| 5 | `hexgrid-outline` | line | 网格描边 `#94a3b8`，0.5px |
| 6 | `stations-heatmap` | heatmap | 密度热力图，默认 `visibility: none` |
| 7 | `weidu-outline` | line | 边界描边 `#0369a1`，2px |
| 8 | `stations-circle` | circle | 站点，**最上层** |

站点圆圈的配色/半径按 `chargeType` 用 `match` 表达式：
`slow` → `#2563eb`/r9，`fast` → `#16a34a`/r7，其余 → `#6b7280`/r7。
**因为数据全是 `unknown`，实际渲染出来全是灰色 r7。**

### 5.2 数据加载（`map.on('load')` 异步流程）

```
① 按 layerGroups 的初始 visible 逐个 toggleLayer()   ← 热力图在这里被设为 none
② 并行 fetch weidu.json + stations.json，失败 throw
③ 绑定 stations-circle 的 click → Popup（name / address / id / type）
④ 内联做一次空间筛选：遍历站点 × 边界多边形，booleanPointInPolygon
     → 得到 52 条 → setData 覆盖 stations source
⑤ weiduStationCount = stationCount = 52
⑥ turf.bbox(边界) → map.fitBounds(padding: 50)
⑦ 给 weidu-fill 加 mouseenter/mouseleave 改光标（只有光标变化，没有点击逻辑）
⑧ fetch hex-grid.json（**失败只给 gridWarning，前面 ③–⑦ 的站点功能保留**）
⑨ 把每格 stationCount 归零，再内联重新统计一遍，按数量写 color
⑩ setData(hexgrid) + loadStatistics() 算右侧面板要用的三个数字
⑪ 绑定 hexgrid-fill 的 click / mouseenter / mouseleave
错误分支：weidu 或 stations 加载失败 → loadError；finally 里 loading = false
```

⚠️ 步骤 ④ 和 ⑨ 都是**页面里另写一遍**的计算，与第 4 章的脚本/工具函数重复。

### 5.3 网格分级配色（阈值写死在 MapView 里）

| stationCount | 颜色 |
| --- | --- |
| 0 | `#f1f5f9` |
| 1 | `#bae6fd` |
| 2–3 | `#7dd3fc` |
| 4–5 | `#38bdf8` |
| ≥6 | `#0284c7` |

实测数据里单格最多 5 个站，所以最深那一档目前不会出现。

### 5.4 交互

| 交互 | 行为 |
| --- | --- |
| 点击站点圆圈 | 弹 Popup（站名/地址/编码/类型）。用 `textContent` 逐行组装 DOM，**天然免疫 XSS** |
| 点击网格 | 先 `queryRenderedFeatures` 查该点有没有站点圆圈，**有就 return（站点优先）**；否则弹网格 Popup 并写入 `selectedHex` |
| 弹窗管理 | 全局只保留一个 `popup`，新建前先 `popup.remove()` |
| 点击柱状图某根柱 | 柱状图 → AnalysisPanel → MapView，`setFilter` 让 `hexgrid-highlight` 只显示 `stationCount === 该值` 的网格 |
| 图层复选框 | LayerControl → toggleLayer → 对该组所有 layer 设 `visibility` |

### 5.5 统计计算（`loadStatistics`）

- `hexCount` = 网格总数（170）
- `occupiedHexCount` = `stationCount > 0` 的网格数（33）
- `hexDistribution` = 按 stationCount 分组计数，升序排列 →
  `[{stationCount: 0, hexCount: 137}, {stationCount: 1, hexCount: ...}, ...]`，
  直接喂给 ECharts 柱状图

`hexCount` / `occupiedHexCount` / `hexDistribution` / `stationCount` / `selectedHex`
全部是 `ref`，通过 props 单向流向 `AnalysisPanel`。

## 七、图层组 ↔ MapLibre layer 对照

`layerGroups` 是"给用户看的开关"，和实际 layer 是多对一关系：

| 组 id | 界面文字 | 包含的 layer | 默认 |
| --- | --- | --- | --- |
| `boundary` | 魏都区边界 | `weidu-fill`, `weidu-outline` | ✅ 显示 |
| `stations` | 充电站 | `stations-circle` | ✅ 显示 |
| `hexgrid` | 六边形供给 | `hexgrid-fill`, `hexgrid-outline` | ✅ 显示 |
| `heatmap` | 密度热力图 | `stations-heatmap` | ❌ 隐藏 |
| — | （无开关） | `hexgrid-highlight` | 常驻 |

`toggleLayer(groupId, visible)` 会先 `map.getLayer(layerId)` 判空再 `setLayoutProperty`，
所以在地图未就绪时调用不会报错。

## 八、口径与坐标系（重要假设）

1. **空间口径**：站点是否属于魏都区，只看坐标是否落在 `weidu.json` 多边形内，
   **不看 `district` 字段**。因此 52 条里有 51 条 `district = 魏都区`、
   1 条 `district = 建安区`（坐标落在边界内）。
2. **坐标系未做转换**：站点来自高德 GCJ-02；`weidu.json` 标注 CRS84 但来源待核实。
   `properties.coordSystem` 只是一个标记字符串，**不会触发任何转换**。
   如果边界实际是 WGS-84，那么现在所有空间筛选结果都存在数百米级偏差，
   需要先确认边界坐标系再复核。
3. **口径统一原则**：地图显示、网格统计、右侧面板统计，三者都用同一批 52 条站点，
   有测试用例（`hexGrid.test.mjs` 第 3 例）守住"网格合计 = 站点总数"这条不变量。
4. **降级策略**：网格数据失败 → 只提示 `gridWarning`，站点照常显示；
   站点数据失败 → `loadError`，整图不可用。

## 九、问题清单与整理建议

### A. 逻辑重复与一致性（最值得先处理）

**1. 网格统计有两份实现，行为还不完全一样**
`src/utils/hexGrid.js` 的 `countHexStations` 有完整校验和"有站点漏出网格就报错"的保护，
但**只被脚本和测试使用**；`MapView.vue` 第 298–310 行另写了一份等价逻辑
（遍历顺序相反、用 `break` 代替 `counted` 标记），没有漏出网格的校验。

> 建议：`MapView.vue` 直接 `import { countHexStations } from '../utils/hexGrid.js'`，
> 删掉内联实现。这样页面与脚本共用一份"唯一真相"，测试也可以直接测页面真实调用的函数。

**2. 运行期在重复构建期已经做过的事**
`public/geojson/stations.json` 在构建期已经筛过（52 条），页面加载后又用
`turf.booleanPointInPolygon` 筛一遍，结果仍是 52 条（当前是 no-op）。
`hex-grid.json` 里脚本已经算好了 `stationCount`，页面又清零重算一遍。

> 两种取舍，需要明确选一个：
> - **信任构建期成果**：页面直接渲染数据，删掉运行期筛选与重算 → 更快、代码更短，
>   但边界或站点数据不同步时不会自我纠正；
> - **坚持运行期自算**：那就删掉 `hex-grid.json` 里的 `stationCount`/`color` 字段，
>   让脚本只负责生成几何，避免"两份数据谁对"的困惑。
>
> 现在这种"两边都算"的状态，问题不在算错，而在于**改动时容易只改一边**。

**3. 残留数据 `data/processed/weidu-stations-by-name.json`**
只有 11 条、没有 `chargeType`、是早期"按 `district` 名称筛选"口径的产物，
与当前空间口径（52 条）直接冲突，并且已经被 git 跟踪。

> 建议：确认无人使用后删除，或移到 `data/legacy/` 并在 README 注明。

**4. `chargeType` 全是 `unknown`**
导致快充/慢充的配色、半径差异和图例说明实际上都不生效，全部灰色。

> 建议：要么去掉这套暂不生效的样式分支，要么补上真实数据源，
> 不要在界面上暗示"快慢充已区分"。

### B. 组件与交互细节

**5. `hexgrid-highlight` 不在任何图层组里**
用户关掉"六边形供给"后，网格填充和描边都消失，但图表点击产生的高亮**依然显示**。

> 建议：把 `hexgrid-highlight` 加进 `hexgrid` 组的 `layerIds`。

**6. 高亮无法取消，且与 `selectedHex` 是两套互不相干的选中状态**
点击柱子会高亮一类网格，但没有任何"清除筛选"入口；点击地图选中的网格也不会
同步到图表或高亮层。

> 建议：面板里加"清除筛选"按钮，并考虑用同一个 `selectedStationCount` 状态
> 统一驱动高亮与面板显示。

**7. 调试输出残留**
`MapView.highlightHexByStationCount`、`AnalysisPanel.handleStationCountSelect`、
`HexDistributionChart.handleBarClick` 三处都有 `console.log`（含"收到 xxx"字样）。

> 建议：删除，或统一走一个可控的调试开关。

**8. 其他小问题**
- `highlightHexByStationCount` 直接 `map.getLayer(...)`，未像 `toggleLayer` 那样判空，
  地图未初始化时会抛错（当前调用路径不会触发，但属于隐患）。
- `loading` 这个 ref 只写不读，模板里没有加载提示，只有测试在用。
- `weiduStationCount` 与 `stationCount` 始终被赋同一个值（52），一个给左上角角标、
  一个给右侧面板，属于冗余状态。
- 站点圆圈有 `stations-circle` 点击，但 `weidu-fill` 只有光标变化、没有点击行为，
  容易让使用者以为边界可点。

### C. 工程与仓库卫生

**9. `node_modules` 被 git 跟踪（3747 个文件）**
`.gitignore` 里虽然写了 `node_modules`，但它在规则加入之前就已经提交，
gitignore 对已跟踪文件无效。

> 建议：`git rm -r --cached node_modules` 后提交（只从索引移除，本地文件不动）。

**10. README 与 `package.json` 与实际流程有出入**
- README 只写了 `convertStations.mjs` + `filterWeiduStations.mjs` 两步，
  **漏了 `buildHexGrid.mjs`**，照 README 跑完不会更新网格数据。
- `package.json` 没有 `test` 脚本，README 让人直接敲 `node --test tests/stations.test.mjs`。

> 建议：README 补上第 4 步并说明顺序；`package.json` 加
