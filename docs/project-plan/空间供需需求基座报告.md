## 0. 一页结论

1. **现状已经具备“基座”的骨架，但还不是“城市需求分布基座”。** 目前有 170 个六边形网格、52 个已记录站点、1,817 条设施 POI、460 条选址参考、1,487 条 OSM 道路，以及“工作日白天／夜间／周末”三档情景需求和道路时间覆盖模型。网格点击只显示需求、供给、失配和站点数量，看不到站内设备、价格、人口、约束证据。
2. **这次要补的不是一张更花的地图，而是一条“从城市通览到单格决策”的链路。** 通览（城市与规划目标）→ 分区（功能区筛选）→ 钻取（网格详情）→ 时段（调价与 24 小时需求）→ 约束（消防、水域、噪声、危险源）→ 出口（契约化导出，供新模块消费）。
3. **需求只能做“相对指数 + 情景”，不能冒充订单或车辆数。** 现有模型是活动强度归一化，三档时间系数是情景假设；在没有订单、人口和站点实测数据之前，任何“某格缺 3 个桩”的结论都只能是待核查建议。
4. **国家标准管的是选址、消防、布置、配建比例和电气安全，不管“服务半径必须 1 公里”。** 本报告把强制条款逐条映射成系统字段和判定；把 1 km、10 分钟、400 m、60 kW 等明确标为情景参数，避免把假设写成规范。
5. **最先要拿到的五类数据**：社区人口与户数、消防站与消火栓、河道蓝线与易涝点、分时电价与站点价格、站点设备与运营实测。拿到之前，页面可以先用现有数据跑通交互，但必须显示“待核查”，不能用 0 或默认值补齐。
6. **建议交付节奏**：两周做出可点的网格详情、功能区筛选和时段模板；再用三到四周接人口、消防、水域和价格；最后做 24 小时曲线、建设规模换算和供新模块使用的版本化接口。

## 1. 定位、边界与术语

### 1.1 这个路由解决什么问题

空间供需路由回答五个问题：

| 问题 | 页面回答方式 | 不回答 |
|---|---|---|
| 需求在哪里、有多强 | 六边形网格分级设色、功能区汇总、人口叠加 | 具体某辆车会来充电 |
| 需求随时间怎么变 | 工作日／夜间／周末三情景，扩展为 24 小时曲线 | 实时订单和排队 |
| 现状供给够不够 | 站点清单、桩数功率、容量指数、覆盖与到站时间 | 真实吞吐量和收入 |
| 哪里不能建、哪里要避让 | 消防、水域、噪声、危险源、易涝约束图层与判定 | 消防设计审查结论 |
| 建设规模大概多少 | 峰时需求 → 建议桩数／功率／配变容量（规划建议值） | 施工图和设备选型 |

### 1.2 基座与新模块的分工

| 能力 | 空间供需（本路由，基座） | 新模块（消费方） |
|---|---|---|
| 需求口径 | 定义、计算、版本号、置信度 | 只读取，不另起口径 |
| 空间单元 | 六边形网格、功能区、社区 | 可聚合到候选场地 |
| 时间维度 | 三情景 + 24 小时曲线 + 电价时段 | 按方案所在时段取峰时或均值 |
| 供给口径 | 站点、桩数、功率、价格、状态 | 可替换为方案新增站点 |
| 约束 | 法定禁建、待核查、警示三级 | 决定候选是否进入比选 |
| 出口 | API + JSON 快照 + CSV | 消费并回写方案，不回写原始库 |

一句话：**基座负责“城市需求与约束的事实和口径”，新模块负责“方案与取舍”。**

### 1.3 术语与口径

| 术语 | 本报告含义 | 不是什么 |
|---|---|---|
| 潜在需求指数 | 五类活动强度按情景系数加权后，用全区固定尺度归一化到 0～1 的相对值 | 不是车辆数、不是订单数、不是 kWh |
| 基础需求指数 | 数据库既有的“住宅 0.5 + 商业 0.5”min-max 指标 | 与情景需求不是同一口径，不能混用 |
| 供给能力 | 桩数 × 单桩功率的配置能力代理 | 不是实测吞吐量 |
| 失配指数 | 需求指数 − 供给指数（同一尺度下） | 不是“缺几个桩” |
| 服务半径 | G2SFCA 的距离衰减参数 d0，默认 1,000 m | 不是国家标准强制值 |
| 覆盖阈值 | 道路时间不超过 N 分钟的判定，默认 10 分钟 | 不是步行可达标准 |
| 调价时段 | 峰、尖峰、平、谷的电价时间窗，可编辑模板 | 不是需求曲线本身 |
| 功能区 | 居住、工作、购物、休闲、公共服务五类主导或混合 | 不是法定用地性质 |
| 约束区 | 消防、水域、噪声、危险源、易涝等影响范围 | 不是最终审批结论 |
| 证据等级 | A 实测／B 官方公开／C 地图推断／D 情景假设／E 缺失 | 不是“可信／不可信”的二元判断 |

### 1.4 用户需求与现状差距

| 编号 | 用户要求 | 现状 | 差距 | 对应章节 |
|---|---|---|---|---|
| R1 | 六边形网格展示城市潜在需求 | 已有 170 格需求／失配／功率专题 | 缺 24 小时、人口、峰时缺口 | 3.3、5.2 |
| R2 | 点击网格显示充电站信息和重要信息 | 只显示站点数量与需求指标 | 缺站内设备、价格、距离、容量、证据 | 3.4 |
| R3 | 可以调价时段 | 无 | 需建时段模板、价格结构、模拟 | 7 |
| R4 | 展示不同时间下的需求 | 只有三档情景 | 需 24 小时曲线和时段联动 | 5.2 |
| R5 | 作为建设标准 | 无规模换算 | 需峰时需求到桩数／功率／配变的换算 | 5.6 |

| R8 | 记录消防设施、河流等影响范围 | 有 39 个水域面和 6 条风险点 | 无消防站／消火栓，无缓冲与判定 | 8 |
| R9 | 人口数据可视化、点击显示 | 未入库 | 需社区级人口和栅格人口 | 3.8 |
| R10 | 符合国家充电站建设标准 | 未做条款映射 | 需标准矩阵、字段、判定、免责边界 | 6 |
| R11 | 供另一个新增模块作基座 | 有部分接口，无稳定契约 | 需版本化 API、JSON Schema、导出 | 4 |

### 2.3 现有模型口径

**基础专题（数据库既有）：**

```text
住宅标准化 = (本格住宅数 - 全区最小) / (全区最大 - 全区最小)
商业标准化 = 同上
基础需求 D = 0.5 × 住宅标准化 + 0.5 × 商业标准化
基础供给 S = 站点数量的 min-max 标准化
失配 M = D - S
四象限按全区平均 D 和平均 S 划分
```

**情景需求（布局规划与道路研究使用）：**

```text
某类活动强度 z(g,k) = 本格 k 类计数 / 全区 k 类最大计数
功能区份额 = z(g,k) / Σ z(g,·)
最大份额 ≥ 50% 为主导功能，否则为混合功能；总强度为 0 为资料不足
固定尺度 K = 全区各格“基础活动强度总和”的最大值
情景需求 D(g,t) = Σ [z(g,k) × 活动系数(t,k)] / K
```

三档情景系数：

| 情景 | 居住 | 工作 | 购物 | 休闲 | 公共服务 | 性质 |
|---|---|---|---|---|---|---|
| 工作日白天 | 0.35 | 1.00 | 0.55 | 0.35 | 0.75 | 情景假设 |
| 工作日晚间及夜间 | 1.00 | 0.15 | 0.80 | 0.80 | 0.45 | 情景假设 |
| 周末 | 0.70 | 0.25 | 1.00 | 1.00 | 0.65 | 情景假设 |

**可达与容量：** Gaussian 2SFCA，d0 = 1,000 m 直线距离，权重 `(exp(-0.5(d/d0)^2) - exp(-0.5)) / (1 - exp(-0.5))`；道路研究使用有向 OSM 网络和速度情景，覆盖条件为道路时间 ≤ 阈值（默认 10 分钟）。两者口径不同，不能混用。

### 2.5 已知局限（必须保留的“不知道”）

- 52 座是“已记录”站点，不是全域普查；可能漏记，也可能包含演示补全属性。
- 1,817 条 POI 是地图检索记录，不代表建筑面积、人口或实际客流。
- 三档情景系数是实验设定，没有用订单或出行调查校准。
- 人口、消防、河道蓝线、分时电价尚未结构化入库。
- 用地数据是 OSM 用途映射，不是法定控规；不能据此判断“可建”。
- 道路速度和信号延时的情景假设，不代表实时车速。
- 站点价格和服务费部分为演示值，不能当作现行收费。

## 3. 目标界面设计

### 3.1 信息架构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：空间供需 │ 城市通览 KPI ×6 │ 情景：工作日白天 ▾ │ 数据时效 2026-10 │
├──────────────────┬───────────────────────────────────────────────────┤
│ 地图              │ 右侧分析面板                                       │
│  ├ 六边形需求      │  ├ 筛选：功能区／指标／时段／约束                  │
│  ├ 功能区图层      │  ├ 网格详情（选中时）                              │
│  ├ 消防／水域缓冲  │  │   需求｜供给｜价格｜约束｜证据                  │
│  ├ 人口热力        │  ├ 功能区汇总（点选或筛选后）                      │
│  └ 站点            │  └ 导出／加入方案                                  │
├──────────────────┴───────────────────────────────────────────────────┤
│ 底部：图例 │ 数据来源与等级 │ 更新时间 │ 免责说明                       │
└──────────────────────────────────────────────────────────────────────┘
```

设计原则：

1. **一屏只回答一个问题**：默认“需求分布”，切到“供给／失配／峰时缺口／人口”时只换设色和详情字段，不换页面。
2. **点击即钻取，不跳页**：网格详情在右侧面板内展开，地图保持上下文；需要方案推演时再显式跳转。
3. **任何结论都带证据**：数字旁边能展开“来源／时间／等级”，没有数据就显示“待核查”，不显示 0。
4. **情景与价格分离**：时间情景改变需求；电价时段改变价格展示；两者只有打开“价格弹性”开关才联动，且必须标注。

### 3.2 城市通览层

建议保留并扩展为 6 个 KPI：

| KPI | 计算 | 空值处理 |
|---|---|---|
| 网格数 | 研究区网格总数 | — |
| 已记录站点 | 当前范围站点数 | 显示“已记录”，不写“全部” |
| 有站网格占比 | 有站网格 / 网格总数 | 注明“不代表服务覆盖率” |
| 需求点 | 带活动类别的需求位置数 | — |

## 4. 数据模型与接口契约（供新模块复用）

### 4.1 主键与坐标

- 网格：`grid_id`（字符串，保留前导零），与现有 `hex_grid.id` 一致。
- 站点：`station_id`（沿用业务 ID），不因导入批次变化。
- 功能区：`zone_id`（POI 法为 `grid_id`；控规法为用地单元 ID）。

## 5. 需求计算口径（建设标准的依据）

### 5.1 潜在需求的定义

潜在需求是“活动强度”的相对表达，不是订单。计算分四步：

```text
① 逐格统计五类活动计数（居住、工作、购物、休闲、公共服务）
② 每类除以全区该类最大值，得到 0～1 强度
③ 按情景系数加权，除以全区固定尺度 K
④ 得到 0～1 的情景需求指数，并保留五类贡献
```

要求：

- 缺失活动计数保留 null，不按 0 处理；某类全缺失时，五类贡献显示“资料不足”。
- 同一格在三档情景之间共用同一个 K；切情景不能拉伸尺度。
- 基础指数（住宅/商业）与情景指数分开命名、分开展示，禁止在同一图例里混用。

### 5.2 从三档情景到 24 小时

推荐分三步走，先做可解释的、再做校准的：

| 阶段 | 方法 | 数据要求 | 用途 |
|---|---|---|---|
| A（现有数据可实现） | 三档系数 + 分类型小时形状插值 | 无新增，需补形状表 | 24 小时曲线、峰谷时刻 |
| B（有订单后） | 用站点分时电量校准形状 | 12 个月订单 | 真实峰谷、容量校核 |
| C（远期） | 出行链／活动链模拟 | 出行调查、手机信令 | 空间错峰与价格弹性 |

A 阶段的默认小时形状（**情景假设，不是实测**，可按功能区调整）：

| 功能区 | 形状要点 | 峰值时段 |
|---|---|---|
| 居住 | 夜间高、白天低，22:00～次日 06:00 为主 | 22:00～24:00 |
| 工作 | 白天高，09:00～17:00 为主 | 10:00～12:00 |
| 购物 | 午后至傍晚高 | 15:00～19:00 |
| 休闲 | 傍晚至夜间高 | 18:00～21:00 |
| 公共服务 | 工作日白天高，午间小峰 | 09:00～11:00 |
| 混合 | 按五类贡献加权叠加 | 由构成决定 |

实现上，先给每类一条 24 点基准形状（和为 1），再乘以该格该类贡献，最后求和。这样切换情景时只需换系数，不重算形状。

### 5.3 功能区判定

| 方法 | 输入 | 优点 | 局限 |
|---|---|---|---|
| POI 主导（现状） | 五类 POI 计数 | 已有数据、可解释 | POI 密度偏差，交通枢纽缺失 |
| 控规用地（待接） | 用地性质、容积率 | 权威、稳定 | 需数据授权与配准 |
| 混合 | 两者叠加，控规优先 | 兼顾 | 规则复杂，需标注来源 |

判定规则保持不变：份额 ≥50% 为主导，否则混合；总强度为 0 为资料不足。增加一条：**POI 与控规冲突时，页面同时显示两种结论**，不静默取其一。

### 5.4 供给与容量

- 供给能力 = 桩数 × 单桩功率（kW），未知不补值。
- 容量服务指数：沿用时间衰减 G2SFCA，基准服务均值归一为 100；无服务时用“每站情景容量／总需求”作固定标尺。
- 覆盖：道路时间 ≤ 阈值；重复覆盖只计一次；不可达需求保留在分母。
- 站点状态：`active` 计入；`maintenance`／`offline` 标注但不计入可用容量；`retired` 不展示、不计入。

### 5.5 失配与缺口

```text
失配 = 需求指数 - 供给指数（同一尺度）
高需低供 = 需求 ≥ 全区均值 且 供给 < 全区均值
峰时缺口 = 峰时需求高于全区峰时均值 且 峰时覆盖率低于阈值
```

“缺口”只用于排序和排查，不直接等于“缺几个桩”。缺桩数需要 5.6 的换算，并经过现场核查。

### 5.6 从峰时需求到建设规模（规划建议值）

给一个可手算的示例，所有参数都标注性质：

```text
① 峰时车次
   N_peak = P × (r_ev / 1000) × f_charge × c_peak
   P：格内常住人口（人）
   r_ev：电动汽车千人保有量（辆/千人），待采集
   f_charge：单车日均充电频次（次/日），待采集
   c_peak：峰时集中系数（峰时电量占比），情景假设

② 所需桩数
   n = ceil(N_peak × T_session / (T_peak × U))
   T_session：单次占用时长（小时）
   T_peak：峰时段时长（小时）
   U：目标利用率（0～1），情景假设

③ 所需功率
   P_need = n × P_pile（kW）
   P_pile：单桩额定功率，默认 60 kW（情景假设）

④ 配变容量
   S = P_need × K_sim / (cosφ × η)
   K_sim：同时系数，情景假设
   cosφ：功率因数，默认 0.9（现有界面默认）
   η：效率，默认 0.9（现有界面默认）
```

示例：P = 3,180 人，r_ev = 30 辆/千人，f_charge = 0.5 次/日，c_peak = 0.35，则 N_peak ≈ 16.7 次；若 T_session = 1 h、T_peak = 4 h、U = 0.6，则 n ≈ ceil(16.7 × 1 / (4 × 0.6)) = 7 个桩；7 × 60 = 420 kW；按 K_sim = 0.8、cosφ = 0.9、η = 0.9，S ≈ 415 kVA。

**这只是演示公式，不是结论。** r_ev、f_charge、c_peak、U 任一未校准，结果就只能作为“建议核查量”。页面必须同时显示参数来源和“规划建议值”标签。

### 5.7 不确定性与置信标记

| 情况 | 处理 |
|---|---|
| 活动计数缺失 | 该类贡献 null，总需求仍可由其他类计算，标“资料不足” |
| 人口未接入 | 不显示千人桩数、不显示车次换算 |

| 约束数据缺失 | 判定为“黄：待核查”，不判绿 |
| 价格未采集 | 显示“未采集”，不显示 0 元 |
| 多源冲突 | 保留两条记录 + 冲突标记，默认显示官方来源 |

### 6.3 消防专项要点

1. **防火间距**按站等级和站外建筑类型查表，系统不预设一个固定数字；一、二、三级站与重要公共建筑主要出入口不小于 50 m。若要把表 11.1.1 的具体数值内置到代码，必须由设计专业录入、标注标准版本，并在标准修订时更新，不能凭经验填数。
2. **耐火等级**不低于二级；车库场景同时执行 GB 50067。
3. **消火栓流量**按等级区分，火灾延续时间不小于 2 h；页面只做“是否具备”提示，流量核定由设计完成。
4. **地下与半地下**：一、二、三级站不应布置；四级确需地下时宜地下一层、靠近车辆出入口。
5. **防火单元**：新建汽车库内集中布置，独立防火单元，采用耐火极限不低于 2.0 h 的防火隔墙或防火卷帘、防火分隔水幕分隔；地下、半地下和高层车库还应设置火灾自动报警、排烟、自动喷水、应急照明和疏散指示。
6. **既有建筑**：未设置上述消防系统的地下、半地下和高层汽车库不得配建分散充电设施。

## 7. 调价时段设计

### 7.1 河南工商业分时电价（2024 年调整）

依据：豫发改价管〔2024〕283 号，2024-06-01 起实施。

| 月份 | 高峰（含尖峰） | 尖峰 | 平段 | 低谷 |
|---|---|---|---|---|
| 1、2、12 月 | 16:00～24:00 | 1 月、12 月 17:00～19:00 | 其余时段 | 00:00～07:00 |
| 3～5 月、9～11 月 | 16:00～24:00 | 无 | 其余时段 | 00:00～06:00、11:00～14:00 |
| 6～8 月 | 16:00～24:00 | 7 月、8 月 20:00～23:00 | 其余时段 | 00:00～07:00 |

浮动比例：高峰∶平段∶低谷 = **1.72∶1∶0.45**；尖峰为高峰的 **1.2 倍**。电价由上网电价与输配电价之和乘以浮动比例，再加线损、系统运行费、政府性基金及附加构成；容（需）量电价不参与浮动。

居民分时（自愿选择）：高峰 08:00～22:00，每 kWh 提高 0.03 元；低谷 22:00～次日 08:00，每 kWh 降低 0.12 元；“煤改电”居民采暖季高峰 08:00～20:00、低谷 20:00～次日 08:00。

### 7.2 站点价格结构

```text
用户支付单价 = 分时电费 + 充电服务费 +（可能的）停车费
```

- 电费：按上述峰平谷时段和浮动比例，随月份变化。
- 服务费：政府指导价或市场调节价，需核实许昌现行标准 ⚠。
- 停车费：按停车场收费规则，可能减免；页面单独显示，不并入单价。

### 7.3 时段模型

| 字段 | 说明 |
|---|---|
| `month_rule` | 月份集合，例如 `[1,2,12]` |
| `start_time` / `end_time` | 左闭右开；跨日拆成两段 |
| `period_type` | `sharp`（尖峰）／`peak`（高峰）／`flat`（平）／`valley`（低谷） |
| `float_ratio` | 相对平段的倍数，例如 1.72、0.45 |
| `policy_ref` | 文件号与条款 |
| `effective_from` / `effective_to` | 生效期 |

编辑器允许用户改边界和比例，但默认加载政策模板；用户改动后显示“自定义”，并可一键恢复。

### 7.4 展示与计算规则

1. 24 小时时间轴同时显示电价色带和需求曲线；游标指到某时刻，显示该时刻的电价、需求、建议桩数。
2. 切换月份时，峰谷时段和电价同步变化；需求曲线不因电价变化而变（除非打开弹性）。
3. “按峰时建设”取 24 小时最大需求；“按日均建设”取算术平均；两者都显示，不隐藏口径。
4. 调价模拟只改展示和测算，不写入正式站点价格表；需要保存时另存为“情景”。
5. 价格弹性的实现：`需求 × (1 + ε × 价格变化率)`，ε 默认 0，范围建议 −0.5～0.5，必须标注“未经本地校准”。

### 8.1 消防设施与消防救援

需要四类数据，缺一不可：

| 数据 | 字段 | 用途 | 现状 |
|---|---|---|---|
| 消防站 | 位置、责任区、车辆、到场时间 | 5 分钟／10 分钟可达圈 | 0 条 |
| 消火栓 | 位置、类型、压力、流量、状态 | 150 m 水源覆盖 | 0 条 |
| 消防水池／取水口 | 位置、容量、取水条件 | 300 m 水源覆盖 | 0 条 |
| 消防通道 | 线、宽度、净高 | 站内与周边通行 | 部分可从道路推断 |

判定逻辑：

```text
若 站点在消防站 5 分钟圈外 → 黄：救援时间待核查
若 站点 150 m 内无消火栓且 300 m 内无水池 → 黄：消防水源待核查
若 站点占用消防车道或登高操作场地 → 红：禁建
若 数据缺失 → 灰：待核查（不判绿）
```

### 8.2 河流水系与防洪排涝

需要：

- 河道蓝线（法定边界）、河道管理范围、堤防保护范围；
- 历史易涝点、积水深度、排水能力；
- 水域面（现有 39 个 OSM 水面可作背景，但不是蓝线）。

判定逻辑：

```text
进入河道蓝线 → 红：禁建
进入河道管理范围 → 黄：需水利部门意见
距历史易涝点 < 100 m → 黄：防洪排涝待核查
位于可能积水场所 → 黄：GB/T 51313-2018 3.0.4 第 6 款
```

现状只有 OSM 水面，没有蓝线和易涝点，因此**当前所有临水网格都应显示“黄：待核查”**，不能因为不在水面里就判绿。

### 8.3 噪声敏感区

依据 GB 3096-2008 声环境功能区：0 类康复疗养区、1 类居住文教区、2 类商业混杂区、3 类工业区、4 类交通干线两侧。充电设备噪声应满足所在功能区限值；居住区夜间尤其敏感。

页面用途：在 1 类、0 类区内新建站时提示“噪声敏感”，并要求提供设备噪声和隔声措施；不做自动否决。

### 8.4 危险源

| 危险源 | 要求 | 来源 |
|---|---|---|
| 加油加气站 | 站内建设充电设施应布置在辅助服务区 | 发改能源规〔2022〕53 号 |
| 甲乙类厂房、库房、液体储罐区 | 一、二、三级站不应设置 | GB/T 50966-2024 3.2.5 |
| 潜在火灾爆炸危险场所 | 不应靠近；毗连时符合 GB 50058 | GB/T 51313-2018 3.0.4 |

现状“风险与障碍”层有 4 个加油点，可作初筛；但没有危化品场所和甲乙类厂房数据，仍需补。

### 8.6 三色判定与证据链

| 结论 | 含义 | 页面表现 | 是否允许进入方案 |
|---|---|---|---|
| 红 | 命中法定禁建或强条 | 红色徽标 + 条款号 | 不允许，除非人工复核 |
